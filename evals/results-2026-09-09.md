# Simulated evaluation — 2026-09-09

Method: an independent agent received eight realistic requests with synthetic
target and scheduler evidence, the collection path, and a prohibition on live
actions. It was not given expected answers or the audit. It read all four
entrypoints and the contract, plan, harness, Slurm, and risk references, then
reported ordered intended actions. No actual remote commands or timers ran.
Model/runtime versions were not independently recorded; this is a qualitative
instruction check in Codex, not a reproducible benchmark or selection-rate test.

Distribution checks: `bash scripts/validate-release.sh` passed (four skills
validated by skills-ref, four discovered by the skills CLI, strict Claude
marketplace validation, and whitespace checks). Shell syntax checks also passed.
The bundled skill-creator quick validator rejected the existing `compatibility`
frontmatter field; its allowlist omits that field, although the
[Agent Skills specification](https://agentskills.io/specification) explicitly
supports it and skills-ref accepted all four files. The field was retained.

| Scenario | Observed decision | Assessment |
| --- | --- | --- |
| Cached status | Read state, label cached with timestamp, no scheduler/target calls | Pass |
| First away monitor | Plan and show, observe-only, RELAXED/30 min, one verified durable heartbeat, no extra approval | Pass |
| Repeated start | Observe current attempt and reuse confirmed active heartbeat | Pass |
| Awaiting-approval wake | Read state and exit without observation or mutation | Pass |
| Final phase | Verify required outcomes/artifacts, overall FINISHED, pause, no next gate | Pass |
| Authorized recovery | LOW repair, new attempt/job ID, reset cursor, preserve key/timer and count retry, verify recovery | Pass |
| One-shot check | Observe and answer without plan/state writes or timer | Pass |
| Expired timer, complete job | Verify completion and preserve expired timer identity; no replacement | Pass |

The evaluator noted ambiguous wording about observing on repeated start.
HARNESSES.md was clarified to require observation on every explicit start;
this matches the evaluator's decision and Watchdog's existing instruction.

Remaining limitations: expiration status is recorded in History rather than a
dedicated field; retry accounting and terminal reporting are instruction-driven,
without implemented transactional persistence or report deduplication. Crash
recovery between a launch and its state write needs a separate integration
exercise before claiming reliable unattended recovery.

Author walkthroughs of the remaining cases: unrelated README progress has no
compute-job trigger; plan-only has no scheduling action; revised phase payloads
invalidate prior approval. These are document checks, not independently measured
skill selection or executed tool traces.
